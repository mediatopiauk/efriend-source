## 9. Hard rules — written for you to follow

These come up because today's session had to keep correcting for them. Lock these in:

1. **Read every source file before touching it.** Even if you've seen it earlier, re-read. Memory is stale.
2. **No freestyling.** When porting Claude Design output, port verbatim. Don't "improve" anything Claude Design didn't ship.
3. **One change per tool call where possible.** The `<strike>` JSX bug today happened because three files got batched. Smaller batches catch errors faster.
4. **Compile-check + brace/paren balance before every output.** `npx esbuild` for each TSX/TS, balance check via grep, before copying to `/mnt/user-data/outputs/`.
5. **CSS extracted from HTML showcases needs the `</style>` tag stripped.** Today's drawer-shell.css build failure came from forgetting this. Always run `grep -n "</\?style"` on extracted CSS before shipping.
6. **`<strike>` is not valid JSX.** Use `<s>`. Update the CSS selector to target both: `strike, s`.
7. **Make decisions per the rules. Don't ask Duncan A/B/C questions when the rules say you decide.** Specifically Reskin Bible §3.
8. **When uncertain about a file's current state, ask Duncan to paste it.** Don't guess.
9. **If you find yourself constructing a 5-piece project plan from a single grep result, you're guessing.** Read more files first.
10. **No em-dashes as stylistic flourish in prose.** Duncan finds them grating. Plain language.
